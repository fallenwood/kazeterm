# 2026-07-13

## Cross-window tab transfer

- Implemented in commit `ebd04ae` (`feat: support cross-window tab transfers`).
- Dragging a tab outside its window creates a new Kazeterm window.
- Dragging a tab onto another Kazeterm window appends it there. Move each tab individually; the empty source window closes automatically.
- Transfers move the existing `TabItem`, `SplitContainer`, `TerminalView`, and underlying terminal entities. They do not recreate the shell or PTY, so running processes, scrollback, terminal content, and split layouts are preserved.
- `DraggedTab` records its source entity/window and uses a shared atomic claim so competing GPUI drop paths cannot transfer the same tab twice.
- Cross-window release handling uses `on_mouse_up_out` and `WindowRegistry` hit testing because platform mouse capture can prevent the destination window from receiving the native drop.
- Destination selection uses GPUI window-stack order where available and activation-MRU order as the Windows/Wayland fallback.
- Transferred terminals receive destination-unique indices and call `TerminalView::rebind_window`. Terminal ownership must be resolved by entity identity rather than terminal index.
- Every per-terminal GPUI subscription is owned by `TabItem::terminal_subscriptions`; subscriptions must be replaced/rebuilt when terminals move between windows, not leaked.

## Independent window lifecycle

- Tear-out windows are independent windows in the same Kazeterm process.
- Closing one window, including by closing its final tab, leaves sibling windows and their terminal sessions running.
- Closing the final remaining window still exits Kazeterm.
- Explicit application-level `Quit` remains global and closes the application.
- The close confirmation UI now refers to closing a window rather than closing the whole application.
- Separately launched Kazeterm processes cannot merge live tabs because GPUI entities and PTYs are process-local.

## Validation

- Cross-window transfer tests cover tab moves, split-pane moves, terminal entity preservation, empty-source closure, and overlapping-window destination ordering.
- Window lifecycle tests cover closing a detached window and closing a window's final tab without affecting sibling windows.
- `cargo test --workspace --quiet` passed after the final changes.
